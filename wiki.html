C01 / 入門

AI Agent 是什麼？

AI Agent 是能圍繞目標選擇行動、使用工具並根據回饋調整的 AI 系統；不代表完全不需要人工。

核心重點

  • 輸入：使用者的目標與約束
  • 判斷：模型規劃目前最適合的下一步
  • 行動：使用工具取得新資訊或完成操作
  • 回饋：檢查結果，必要時重試或結束

日常例子： 請幫我規劃讀書：不只是回答建議，也能讀取行事曆、整理任務並再次檢查時段。

常見誤解： 不是每個聊天機器人都是 Agent。

C02 / 入門

LLM、Workflow、Agent 的差異

LLM 回覆單次請求；Workflow 按預設步驟執行；Agent 可在允許的範圍內動態決定下一步。

核心重點

  • LLM：通常一次問答或生成
  • Workflow：路徑固定，可預測、易測試
  • Agent：模型選擇下一步或工具，彈性較高
  • 沒有「一定越自治越好」，以任務需求決定

日常例子： 摘要文章→翻譯→排版屬固定 Workflow；遇到不明內容自行決定查哪一份資料更偏向 Agent。

常見誤解： Workflow 包含 LLM 不等於一定是自主 Agent。

知識引用：S02 S05
C03 / 基礎

Agent 的三個核心元件

Model 負責判斷、Tools 負責對外讀取或執行、Instructions 定義任務、界線與輸出規格。

核心重點

  • Model：理解上下文與選擇動作
  • Tools：搜尋、計算、查資料庫、寫入等
  • Instructions：角色、限制條件、停止條件
  • Guardrails／驗證：防止越權與格式錯誤

日常例子： 旅行助手：模型挑景點，工具查營業時間，指令限制預算和地區。

常見誤解： 工具不能只給名稱，還需要清楚的用途與參數。

知識引用：S01 S03
C04 / 核心

Model–Tool–Observation Loop

當資訊不足時，模型選擇工具；工具回傳 Observation；模型根據新資料再決定下一步或輸出答案。

核心重點

  • Thought / Decision：選擇需要的動作
  • Tool Call：帶著參數呼叫適當工具
  • Observation：取得工具的回傳結果
  • Evaluate：達標則停止；未達標則重試或尋求人工協助

日常例子： 查詢課堂時程 → 找到資料 → 發現衝堂 → 改選其他時段 → 輸出可行版本。

常見誤解： 不能無限制重試；需要步數上限與失敗退出條件。

知識引用：S03 S01
C05 / 核心

查詢 Wiki：先檢索，再回答

把外部來源整理成可追溯的知識項，回答或生成投影片時先找有關內容與來源，再做摘要。

核心重點

  • Ingest：整理每篇來源的重點與 URL
  • Index：以主題／標籤／關鍵字建立索引
  • Retrieve：依問題挑選相關知識項
  • Ground：只把有來源支持的事實放入簡報

日常例子： 產生「什麼是 Tool Use？」之前，先檢索 C03 和 C04，附上 S01、S03。

常見誤解： 檢索不足或來源對錯頁，容易生成看似合理卻無根據的陳述。

知識引用：S01 S03
C06 / 進階

Workflow Graph 的三種形式

節點是任務、箭頭是依賴與條件；順序、分支、迴圈可組合，必要時加入平行處理。

核心重點

  • Sequential：完成前步才執行下一步
  • Routing：依條件決定不同路徑
  • Loop：檢查失敗回到先前步驟
  • Parallel：可獨立的工作同時進行

日常例子： Wiki 生成：檢索來源 → 整理摘要 → 查核 →（不合格則返回檢索）→ 排版。

常見誤解： 不應把每個簡單任務都拆成複雜的多 Agent。

知識引用：S02 S04 S05
C07 / 進階

驗證與 Human-in-the-loop

讓系統在輸出前檢查來源、格式、任務限制和高風險動作；無法自動確認的部分交由人核對。

核心重點

  • 來源查核：事實是否能對應原文與來源 ID
  • 格式查核：簡報是否完整、可讀
  • 安全查核：需要寫入資料時先確認權限
  • 失敗回路：未通過則重新檢索／改寫

日常例子： 一頁簡報未附來源 → 驗證器阻擋發布 → 補上相符的 Wiki 引用 → 再次驗證。

常見誤解： 單純「請 AI 自己檢查」不足以保證真實性；結構化規則與人工驗證很重要。

知識引用：S01 S02 S05
C08 / 案例

實例：讀書規劃助理

將抽象的 Agent loop 放進有具體停止條件的學生日常任務。

核心重點

  • Goal：安排 3 天讀書進度
  • Retrieve：讀取科目、截止日期與既有時段
  • Plan：依優先順序分配時數
  • Check：檢查衝堂與時數，失敗就重排

日常例子： 衝堂發生→重新搜尋空檔→更新計畫；通過檢查才輸出。

常見誤解： 此例是示意流程，沒有實際連動使用者行事曆。

C09 / 反思

何時不該使用 Agent？

如果任務規則固定、可用程式函式直接解決，先用較簡單的 Workflow 或一般程式更可靠。

核心重點

  • 固定算式：直接寫函式
  • 穩定的步驟：順序 Workflow
  • 資訊複雜且路徑不明：考慮 Agent
  • 評估成本：可靠度、延遲、費用、可解釋性

日常例子： 計算課程學分不用 Agent；處理不同課表限制可能需要多步查詢與反覆修正。

常見誤解： Agent 能力更強不等於每項任務都應交給 Agent。

知識引用：S02 S05
