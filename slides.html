01 / 起點

你已經用過 LLM，但 Agent 多做了一件事

LLM / 單次回答「給我讀書建議」

根據已知資訊產生一段文字，通常沒有真的查詢或更新你的資料。

AGENT / 目標導向「幫我排好讀書計畫」

可以判斷要查哪些資料、使用工具、發現衝堂後重新安排。

關鍵差別：不只產生文字，而是能執行可檢查的步驟。
來源：S01 S02 S03 S05 · Wiki：C01 C08
02 / 核心概念

LLM、Workflow、Agent 有什麼不同？

01LLM

接收輸入，直接生成回答。

02Workflow

程式預先決定「先做 A 再做 B」。

03Agent

模型可根據任務狀態，動態決定下一步與工具。

不是越「自主」越好：固定任務優先選簡單 Workflow。
來源：S02 S05 · Wiki：C02 C09
03 / 組成

設計 Agent 需要三個元件

01 / BRAINModel

理解目標、規劃下一步、判斷結果。

02 / HANDSTools

查詢網頁、計算、讀寫資料等能力。

03 / RULESInstructions

定義角色、限制條件、輸出格式、何時停止。

沒有權限與檢查機制，再好的工具也可能被用錯。
來源：S01 S03 · Wiki：C03
04 / 運作

看懂 Agent Loop

每次動作結束後，新的 Observation 都會改變下一步判斷。

Model 決策
→
Tool 呼叫
→
Observation
→
Evaluate
若未達成目標，Evaluate → 回到 Model；若通過檢查，就輸出並停止。
來源：S01 S03 · Wiki：C04
05 / 工具

Tool Use 不只是一個搜尋按鈕

READ查資料

搜尋官方文件、查詢行事曆或知識庫。

COMPUTE算與整理

計算時間、比對資料、轉換格式。

ACT執行動作

修改資料或發送通知，需要額外權限與確認。

一個好的 Tool 需要清楚的名稱、輸入參數、輸出格式與錯誤處理。

07 / Graph

Graph 讓流程更可控

SEQUENTIAL順序

取得資料 → 整理 → 輸出。

ROUTING分支

需要查證？是 → 查 Wiki；否 → 繼續。

LOOP重試

驗證失敗？回前一節點修正，通過才發布。

複雜任務也可並行處理獨立的子任務，但應先確認真的有需要。

09 / 品質

沒有驗證的 Agent 很難可靠

01 / SOURCE有證據嗎？

每個重點都能對應 Wiki 與官方來源。

02 / FORMAT能使用嗎？

標題、排版、按鈕及連結是否正常。

03 / SAFETY可以執行嗎？

外部動作先檢查權限，必要時要求人工確認。

檢查應前移：在摘要進簡報之前，先驗證引用與來源 ID。
來源：S01 S02 S05 · Wiki：C07
10 / 小測驗

你分得出 Workflow 和 Agent 嗎？

某個系統按照固定程式規則：先摘要文章、再翻譯、最後排版。它最接近哪一種？
A. LLM 單次問答B. WorkflowC. 完全自主 Agent
答案 B：Workflow。步驟與路徑已事先固定；即使中間用到 LLM，也不一定是自主 Agent。
來源：S02 S05 · Wiki：C02
11 / 總結

記住這三句話

01Agent 有目標

不只是輸出一段文字。

02Loop 有回饋

用工具結果持續調整，達標即停止。

03Graph 有檢查

清楚設計重試、引用與人工確認。
