1. LLM Wiki 主題與簡介

本 Wiki 的目標，是讓對 AI Agent 沒有背景的學生，從日常問答出發，逐步學到 Tool Use、Agent Loop 與 Graph 的基本概念。先規劃教學目標與課綱，再整合官方文件，建立 9 個有來源追溯的知識節點。每個節點都有摘要、核心重點、實例、常見誤解與來源 ID。

4. Loop／Graph 設計

資料取得→Ingest→Wiki 檢索→摘要改寫→內容查核→HTML 簡報
Loop A — 來源不完整：取得資料 → 整理 → 來源驗證 → 若失敗則返回資料取得。
Loop B — 內容無法追溯：Wiki 檢索 → 重點改寫 → 引用檢查 → 若失敗則返回 Wiki 檢索。
Loop C — HTML 不可用：產生 HTML → 結構與互動驗證 → 若失敗則重生 HTML。

這樣的 Graph 可分辨「資料錯誤」與「輸出錯誤」，不用每次都從頭重做。尤其把來源檢查移到產生 HTML 之前，可降低後續返工成本。完整 Mermaid 流程圖、節點定義和原因見 workflow.md。

6. 反思與調整

哪個節點容易出錯？

在「Wiki 知識 → 投影片」這個轉換步驟，容易遺漏來源 ID，造成簡報雖然能讀，卻無法回查證據。此次測試確實確認驗證器可以攔截這種情況，但沒有足夠的多次執行紀錄來統計最常發生的錯誤類型。

檢查移到哪個步驟？

從「HTML 完成後才查核」改成 Wiki 檢索後、投影片摘要前先查來源 ID；HTML 產生後再做第二輪引用與功能檢查。

為何修改 Workflow／Graph？

因為來源問題應回到資料／摘要節點處理，畫面問題則回到排版／HTML 節點處理。雙層驗證能更快定位錯誤，也讓結果更容易重現與審核。

實作界線：本專案使用 LLM 協助整理官方知識與製作教學內容；執行時的生成器為可重現的本地 Python 程式。Wiki 可離線檢索，但並非直接串接線上 LLM API 或自動爬取原始網頁全文。成果可直接在瀏覽器檢視。
